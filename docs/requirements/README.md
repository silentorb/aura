# Requirements

Product definition and behavioral requirements for Aura.

## What belongs here

- Vision, goals, and non-goals
- Feature requirements and acceptance criteria
- User-facing behavior specifications
- Constraints that code must satisfy

## What does not belong here

- Implementation details (see [`../design/`](../design/))
- One-off task notes or scratch work
- Architecture decisions with rationale (see [`../decisions/`](../decisions/))

## How to write requirements

- State *what* the system must do, not *how* to implement it.
- Use clear, testable language where possible.
- Link to related design docs and ADRs when they exist.

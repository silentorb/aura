# Design

Architecture and system design for Aura.

## What belongs here

- System architecture and component diagrams
- Module boundaries and interfaces
- Data flow and interaction patterns
- Technical constraints and trade-offs under consideration

## What does not belong here

- Product requirements (see [`../requirements/`](../requirements/))
- Finalized architectural decisions with rationale (see [`../decisions/`](../decisions/))

## How to write design docs

- Describe structure and relationships, not line-by-line implementation.
- Mark undecided areas explicitly as TBD.
- Promote settled choices to ADRs in [`../decisions/`](../decisions/).
